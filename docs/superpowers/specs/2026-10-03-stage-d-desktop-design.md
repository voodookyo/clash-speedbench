# 阶段 D：桌面客户端、安装与生命周期

日期：2026-10-03。状态：规格已确认，等待共享后端/界面。依赖：共享后端/界面 A–C。

## 架构选择与范围

Tauri 2 负责窗口、单实例、托盘、通知、受限 OS 集成和后端进程管理。测量仍由现有 Python/curl/Mihomo 执行，不增加第三方 Python 运行依赖。

桌面包包含固定版本 Python 运行时/必要标准库、Python 源模块、静态前端、许可证与完整性清单；无需用户安装 Rust、Node 或 Python。核心源码仍支持 Python 3.9/3.12，桌面内置运行时版本单独固定并记录维护策略。

既有 CLI/Web/启动器继续可用。不将桌面 EXE 仅实现为打开默认浏览器的快捷方式。

Tauri 官方支持 sidecar，但实际运行时采用随包 Python 可执行文件 + 参数白名单。不能赋予前端任意 shell/文件读取权限。Windows 初始验收成功后完成 macOS/Linux 对应包与构建测试；每个平台分开记录实测证据。

## 后端生命周期

桌面持有自己启动的 backend PID 与 instance_id，握手校验 app_id、协议/版本、启动 nonce；端口已开不等于 SpeedBench 已启动。

仅绑定 127.0.0.1，可使用系统分配空闲端口，避免与8950旧 Web 冲突。浏览器独立入口默认8950保持不变；desktop 与独立 Web 不能同时启动两个测速任务，使用数据目录级所有权机制和真实 PID/instance 验证协调。不能只凭残留锁文件认定进程活跃。

桌面在 loopback 中加载同源共享页面，保留其写 token 与 Host/Origin 校验。nonce/token 经私有管道/受保护握手传递，不进 argv、URL、日志或 localStorage。不得为了 `tauri://` Origin 通配放行；需要协议桥时使用明确的本实例认证桥且重新验收。

关闭窗口默认隐藏到托盘，任务继续；菜单“退出”先请求取消、等待清理、再关闭自有 backend。超时强杀只限本应用启动的 backend 与其 worker 子树，不能按进程名杀掉用户 Mihomo。

Windows 验证 Job Object/子进程归属与崩溃清理；macOS/Linux 验证进程组与信号。强杀失败保留明确诊断，不报告虚假退出成功。休眠/唤醒使在途测量异常时标 partial，并允许用户重试，不自动重新耗费流量。

重复启动激活现有窗口，不启动第二后端。升级安装前检查是否存在活跃任务，不能直接覆盖运行中的文件。

## 桌面交互

窗口具有应用图标、记住尺寸/位置、系统主题、最小尺寸与托盘菜单。托盘提供打开、任务状态、取消、退出，不默认周期测速。

完成通知只显示脱敏摘要，可关闭；手动切换仍经后端验证和认证。外链只允许受控 HTTPS 目标，通过系统浏览器打开；订阅提供的文本不能成为任意 shell 参数。

泄漏页内嵌测试只代表系统 WebView，不代表 Chrome/Edge；系统浏览器审计需要独立环境标识。Linux WebKitGTK 的 WebRTC 能力缺失时明确无法确认，不移除该页或报无泄漏。

## 安全边界

- 本地固定资源加载、CSP、静态白名单、HTML escaping、严格外链导航拦截。
- 前端不具备通用 filesystem/shell 权限；只有明确允许的窗口/托盘/诊断/外链命令。
- 不从任意远程网页载入具有本地 IPC 权限的内容。
- provider/controller Key 仍只驻留 Python 后端；桌面命令与通知不得获得/回显。
- 私有数据/种子/token 存数据目录，不放应用安装目录或 bundled assets。
- 完整性清单禁止纳入用户历史、日志、Key、seed 和订阅配置。
- 安装包依赖、运行时及更新来源固定，可校验；不运行下载到的未知脚本。

## 包与发布

Windows：独立 EXE 构建验证，并提供可安装包及便携包；声明 WebView2 检测/安装策略，离线无 WebView2 时明确错误。不能宣称绝对单文件免运行时。

macOS：架构对应运行时和 `.app`/DMG或ZIP，兼顾 Intel/Apple Silicon 分包；不能以 Windows EXE 测试代替签名/Gatekeeper/运行验证。

Linux：发行格式及 WebKitGTK/curl 系统依赖列明；构建与运行环境区分。源码 Web 后备入口保持可用，但它不是 Linux 桌面包验收的替代。

CI 新增桌面构建/资源完整性/前端任务，不删除六格 Python 测试。依赖锁文件入库。产物附版本、平台/架构、SHA-256、运行时版本和许可证；本机生成包留在 dist，不提交二进制。

缺少商业签名证书时明确标 unsigned 和系统提示，不伪称 signed。内置自动更新仅在有用户提供的可信签名密钥与正式发布源后开启；在此之前交付版本检查、官方链接与可验证手动升级，不能实现不验签自更新。

没有用户新授权，不 push/tag/Release。此次目标允许完成代码与本地包，不自动改变 GitHub 状态。

## 数据迁移与回退

Windows/macOS/Linux 继续现有应用数据目录；不把测试数据迁入或覆盖真实历史。新表/列幂等添加，raw 不变。备份包括 JSONL、SQLite一致性快照、偏好、新身份种子；seed 不得上传作为诊断材料。

首次桌面启动引导发现既有历史并展示路径，仅在用户选择时导入其他目录。旧浏览器收藏只能由用户从旧界面显式导出/导入非敏感偏好，桌面不能读取任意浏览器 profile。

旧版仍能读取已有 raw/兼容字段；新独立表忽略即可。回退前备份，不为回退删除新历史。新旧程序不能同时写同一 JSONL。

真实下载目录安装替换需在新包验收后进行：先备份，确认无活跃测量，再切换安装文件，保存历史与密钥策略，不自动重启 Verge 或修改系统代理。

## 验收

1. 干净 Windows 无系统 Python/PATH时可打开独立窗口并连接 Verge。
2. 双击第二次只激活现有实例；无应用后端但其他服务占端口时正确处理。
3. 关闭窗口、托盘打开、通知、取消、退出、强杀、应用崩溃、后端崩溃与休眠恢复。
4. 临时 worker 最终不存在，用户 Verge/Mihomo/其他进程不受伤害。
5. 旧8950 Web 与新客户端协调写入与任务，不重复测速或弄坏历史。
6. 起停/升级前后真实历史 raw 行数与内容哈希不变，旧轮次回放和新轮次写入正确。
7. 所有包中文/空格路径、emoji、不同工作目录下可运行；缺 curl/WebView/运行时有明确错误。
8. 密钥 canary、远程导航、Origin/Host、IPC参数、路径权限与种子保密验证。
9. 每个平台独立的 build、package 与运行验收证据；对应环境缺失时保持该项未验收。
10. README 给出安装、数据位置、升级、回退、系统依赖、签名限制与环境泄漏边界。

完成标准：提供真实独立桌面客户端与可验证包，不用仅有构建配置或浏览器启动脚本冒充交付。商业签名/自动更新没有所需密钥时不算安全功能缺陷，但必须明确限制和禁用状态。
