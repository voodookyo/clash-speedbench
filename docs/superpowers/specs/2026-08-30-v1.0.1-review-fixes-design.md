# Clash SpeedBench v1.0.1 review fixes design

## Scope

This patch addresses only the three defects confirmed during the v1.0.0
release review:

1. Parse the current official IPinfo `as` response object without breaking
   compatibility with older `asn` fixtures.
2. Make the cleartext transport boundary of the free ip-api provider explicit
   and give privacy-sensitive users a supported opt-out while preserving the
   existing no-key default.
3. Prevent the Windows cancellation unit test from writing the production
   `cancel-request` sentinel into the repository.

No classifier thresholds, benchmark data flow, database schema, paid-provider
API contract, Web UI layout, or release artifact format changes are in scope.

## Root causes

### IPinfo

The current `api.ipinfo.io/lookup/{ip}` schema exposes ASN metadata under the
top-level `as` object. `IpInfoProvider` and its tests instead read a synthetic
`asn` object, so official responses lose ASN, AS name/type, ISP, and
organization evidence.

### ip-api

The official free JSON endpoint is HTTP-only. SpeedBench intentionally keeps
it as the no-key basic provider, but v1.0.0 documentation does not disclose
that transport limitation and users cannot disable the request independently.

### cancellation test

`test_terminate_timeout_escalates_to_kill` follows the real Windows branch and
therefore writes `speedbench_web.CANCEL_FILE`, whose default location is the
repository root in a source checkout.

## Chosen design

### IPinfo compatibility parsing

- Prefer a mapping in `payload["as"]`.
- Fall back to a mapping or scalar in `payload["asn"]` for compatibility.
- Preserve the existing `company`, top-level ISP/organization, privacy, and
  missing-field behavior.
- Add an official-schema fixture that proves ASN, name/type, ISP, organization,
  and Corporate/Business classification evidence survive normalization.

### ip-api disclosure and opt-out

- Preserve ip-api as enabled by default so no-key installations retain v0.x
  behavior.
- Add `SPEEDBENCH_DISABLE_IP_API=1` as an explicit environment opt-out.
- A disabled provider must report `disabled`, make no transport request, and
  remain visible in provider status reporting.
- Document that the official free endpoint is cleartext HTTP, sends no API key,
  cannot independently produce IP Quality Score/Grade, and may be disabled.
- Do not silently switch to an unsupported HTTPS URL or add a dependency.

### isolated cancellation test

- Patch `speedbench_web.CANCEL_FILE` to a path inside `TemporaryDirectory` for
  the escalation test.
- Retain the existing platform-specific production behavior and escalation
  assertions.
- The full test suite must leave no new root-level `cancel-request` when it was
  absent before the run.

## Verification

- New official-schema IPinfo regression test fails before and passes after the
  parser change.
- New ip-api opt-out tests verify `disabled` status and zero transport calls.
- Focused provider and cancellation tests pass on the current Windows host.
- `python -m unittest discover -s tests -v` and Python 3.12 both pass.
- `git diff --check` passes and no source/package dependency is added.
- No push, merge, tag, or release is performed.
