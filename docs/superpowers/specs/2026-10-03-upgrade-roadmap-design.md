# Clash SpeedBench 产品化升级：总设计与验收路线

日期：2026-10-03。状态：用户已明确回复“规格确认，继续实施”；进入分阶段实施。

## 目标与范围

在现有 Python + curl + Mihomo 架构上完成四个阶段：

1. A：修正订阅归属、节点身份与历史查询。
2. B：提供快速/标准/深度/IP 专项任务，优化调度并实时展示结果。
3. C：将技术参数入口改成任务导向界面，保留高级设置与完整证据。
4. D：交付真正的桌面客户端，复用同一 Python 后端和界面。

本目标不是仅完成一份计划或一个网页外壳。交付必须包括代码、测试、安装/打包路径、迁移说明和逐项验收记录。没有证据的功能不得标记为完成。

## 已核对的基线

- 工作分支 `codex/fix-controller-autodiscovery`；设计开始时 HEAD 为 `32e21dd`，工作树干净。
- README 当前版本 v1.0.1。最近提交包含控制器自动发现和认证修复，尚未因此发布新版本。
- 现有核心包含 Phase 1 并发粗筛、Phase 2 节点间串行带宽精测、独立 worker、串行回退与恢复、IP 情报缓存、SQLite/JSONL 历史、Web 泄漏审计。
- UI 仅传递 include、MB、rounds、auto_switch；默认 30MB，CLI 默认精测 Top 15。
- UI 轮询文本日志，用正则解析进度；只有任务终止后才刷新节点结果。
- 出口 IPv4/IPv6 与基础画像已经并发，但当前执行器会等待三者全部结束。
- Phase 1 使用静态分片；计时起点在 DoH 预解析之后，不能代表完整用户等待时间。
- 当前订阅字段来自 `/proxies` 的 `provider-name`。只读本机核对：40 个叶子节点均为空；Verge 有两个具名远程订阅；所有 40 个节点同时出现在多个 provider 成员集合中。
- 本机历史数据库只读核对：43 轮、1,304 条节点记录，provider 均为空。旧历史来源不能从当前配置反推。
- `node_key` 为 proto/server/port 的短哈希，不区分订阅和不同认证配置；前端收藏/展开/趋势多数依赖名称。
- 现有 macOS `.app` 和 Windows启动器最终打开浏览器，不是独立桌面窗口。
- GitHub Actions 核心测试矩阵为 Ubuntu/macOS/Windows × Python 3.9/3.12；无 pip 安装步骤。
- 本机已有 cargo、rustc、Node、Python；不代表桌面编译、WebView、签名或其他平台打包已经验收。

上述运行数据只用于定位，不包含订阅 URL、节点凭据、控制器密钥或第三方 API Key。本轮规划未启动测速、未切换节点、未修改用户配置。

## 架构与模块边界

保留现有测速函数与 provider 业务层；以可单独测试的适配模块增加能力：

| 单元 | 责任 | 消费方 |
|---|---|---|
| 订阅目录/身份适配 | 读取安全元数据、解析来源证据、建立稳定身份 | CLI、worker、Web、历史 |
| 任务配置 | 将模式与高级参数校验为同一配置 | CLI、Web、桌面 |
| 任务事件与计时 | 输出结构化状态、增量结果、阶段耗时 | Web、桌面、诊断记录 |
| 调度适配 | 分阶段候选、动态 worker、小流量任务预算 | 现有测速引擎 |
| 共享前端 | 任务导向交互、表格与详情、订阅/历史/泄漏 | 浏览器、桌面 WebView |
| 桌面外壳 | 后端生命周期、单实例、托盘、窗口、安装 | Windows/macOS/Linux |

不将测速引擎重写成 Rust，不将所有函数合并成新大文件，不新增测速网站。版本化 JSON 接口将新前端与旧兼容接口隔离。

## 方案选择

桌面采用 Tauri 2 + 系统 WebView + 随应用分发的 Python 后端。相比继续浏览器入口，它能提供真正的窗口和生命周期管理；相比 Electron，它不另外嵌入 Chromium/Node 运行时，但必须验证系统 WebView 差异。

保留源码 CLI 与 Web 入口。Python 核心继续只依赖标准库和系统 curl；桌面开发/打包新增 Rust 与前端构建依赖，必须列明并锁定版本，不能称为整个开发工程零依赖。

Windows 桌面包先验收，随后完成 macOS/Linux 的桌面打包与验证。这是顺序，不是取消其他平台的交付。没有在对应平台运行的结果必须明确标注为未验证。

每阶段均执行：失败用例/fixture → 修改 → 专项测试 → 全量测试 → 集成验收 → 小粒度本地提交。C 的视觉设计可以提前开展，但不得绕过 A/B 的接口和数据出口；D 的发布不应先于共享后端稳定。

实施计划在书面设计确认后展开为带文件责任、命令与可判定结果的任务清单。没有授权自动推送、创建 Release、合并或发送其他线程消息。

## 不变约束

1. 保留延迟、jitter、TCP/TLS connect、单流/多流、探测成功率、Phase 1/2、worker 与串行回退。
2. 带宽精测节点间串行；同一节点的多流是明确选项，不能与跨节点并发混淆。
3. 不因缺失 IP 情报而赋满分，不把未测带宽当作零带宽，不用稀疏测试冒充完整评估。
4. 保留住宅与住宅代理、多源证据和冲突逻辑，供应商缺失不妨碍网络测速。
5. API Key 和控制器密钥不返回前端，不进日志、JSONL、CSV、SQLite raw，也不发给被测节点。
6. 后端只绑定 127.0.0.1；继续 token、Host/Origin、静态白名单、HTML escaping。桌面不能以兼容性为由关闭检查。
7. 不默认执行订阅脚本、不自动切换未加载订阅、不擅自改 Verge 配置。
8. 不删除/重写既有 `runs.raw`；新增字段与表可幂等迁移。
9. 保留用户数据与无关工作树修改；不覆盖正在运行的旧安装，不全局改变 Python/PATH/代理配置。
10. 不使用第三方网页爬取替代官方 API；DNS 继续 Guided Audit，除非另有正式 observer 协议。

## 统一验收矩阵

| 要求 | 权威证据 |
|---|---|
| A 来源正确 | 脱敏 Verge/Mihomo fixture；只读本机映射报告；未知/多来源用例 |
| A 身份隔离 | 同名、同服务器不同订阅/凭据、改名与密码轮换测试 |
| 历史兼容 | 旧 schema/JSONL 导入及原始行哈希不变，迁移重复执行 |
| B 模式正确 | 配置校验、CLI/Web 一致性、采样覆盖范围测试 |
| B 调度有效 | 可控慢任务测试、计时记录、同参数基线对照，不能只比较不同覆盖量 |
| B 实时/恢复 | 增量事件、序号重连、终态唯一、刷新重接、取消/强杀清理 |
| C 可用性 | 渲染界面证据，筛选/模式/结果/切换/历史实际操作，键盘和错误态 |
| 安全 | 密钥 canary、路径边界、参数上限、权限、Origin/Host、XSS 与外链测试 |
| D Windows | 桌面构建日志、实际 EXE/安装包、独立窗口、托盘与后端清理、干净环境验证 |
| D macOS/Linux | 各自构建与运行/安装证据；仅 CI 编译不冒充完整真机验收 |
| 升级保留数据 | 升级前后 raw 行数/哈希、数据目录、回放和回退记录 |
| 回归 | `python -m unittest discover -s tests -v` 与六格核心矩阵；新增前端/桌面测试 |

CI 使用 mock fixture，不调用付费 API。真实性能验收需限定节点数、流量预算与网络环境，记录是否触发串行回退。不得用 mock 时间宣称真实网络提速。
