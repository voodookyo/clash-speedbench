# Clash Verge 控制器自动发现与认证修复

日期：2026-10-02。范围：SpeedBench CLI、Web 后端和 Windows 下载版。

## 目标与已批准方案

双击启动 SpeedBench 时，无需每次手动设置 MIHOMO_SECRET，即可连接当前本机 Clash Verge 控制器。
用户已批准自动读取本机运行配置、保留显式配置优先级、统一认证入口、安全失败和测试后更新下载版的方案。
本文件是该方案的细化；代码实现须在用户审阅本文件后开始。

## 已确认的根因

- 当前 CLI 从 --secret 或 MIHOMO_SECRET 获得密钥。
- Web 的 get_current 和 do_switch 只读取 MIHOMO_SECRET；测速子进程继承父进程环境。
- 本机 Verge TCP 控制器不带认证时返回 401；使用其当前配置密钥时，可以读取版本、配置和节点。
- 新版运行配置包含动态 Windows 命名管道名称，不能只依赖旧的固定管道名称。
- 无控制台的 Web 测速子进程不应进入 getpass 交互。

不将上述现象描述为 v2.5.6 首次引入认证；没有证据支持这个版本因果判断。

## 方案选择

采用读取 Verge 本机运行配置的产品修复。用户级环境变量虽可持久化，但会保存额外密钥副本、随密钥变化失效；
写入启动脚本易泄露和被升级覆盖。本次不采用这两种方案，也不取消控制器认证。

## 组件与数据流

增加独立、仅使用标准库的控制器配置发现模块，避免导入 worker 模块导致循环依赖。
该模块负责候选配置路径、顶层控制器字段读取、地址规范化、密钥与地址绑定。
现有 MihomoAPI 继续负责 Unix socket、Windows named pipe 和 TCP 传输，不改测速实现。

调用链为：CLI/Web -> 解析连接候选 -> 用对应密钥进行只读 /version 验证 -> 现有业务逻辑。
CLI、当前节点查询、节点切换和 Web 测速启动均使用统一解析入口。
Web 测速启动先验证连接，失败则明确退出；子进程通过统一入口解析，不把密钥放入命令行。

## 配置发现与优先级

- 显式 --controller 限定目标，不偷偷切换到其它实例。
- 显式 --secret（包括空值）优先于 MIHOMO_SECRET；未显式传入时，存在的环境变量优先于自动发现。
- 没有手动密钥时，只能将本机配置密钥用于与该配置声明匹配的本机地址或 IPC 通道。
- 未指定地址时，先尝试本机运行配置中的通道，再保留现有默认地址探测作为兼容回退。
- 自动读取不覆盖手动错误密钥；手动认证失败应提示检查手动配置。
- 对不匹配的显式地址（尤其远程地址），禁止附带自动发现的本机密钥。

优先读取 clash-verge.yaml（运行配置）；读取同目录 config.yaml 作为运行配置缺失时的回退。
Windows 检查现有 APPDATA Verge 路径；macOS 检查现有 Application Support 路径；
Linux 检查 XDG_CONFIG_HOME 或 ~/.config 下的 Verge 配置路径。不存在的配置不阻断旧版默认探测。
存在但损坏或无法读取的运行配置只生成脱敏诊断，不拼接来源文件内容。
多份配置作为独立候选处理，绝不将一个文件的地址与另一文件的密钥混用。

仅提取顶层 external-controller、external-controller-pipe、external-controller-unix 和 secret。
采用明确限定的标量解析，不执行 YAML、不依赖 pip，也不需要解析完整订阅或 proxies。
覆盖 Verge 生成的单双引号、反斜杠、引号内 # 和冒号；不支持的语法拒绝自动认证并提示手动配置。
缺失/null/空密钥视为无密钥；拒绝密钥中的 CR/LF，防止 HTTP header 注入。

自动发现的 TCP 目标仅允许明确的本机 loopback；配置为 0.0.0.0 或 :: 的监听地址归一到 loopback。
拒绝配置中的远程主机、URL 凭据、查询参数和片段，不通过域名解析推断“本机”。
Windows 管道仅允许本机管道形式，不连接远程 UNC 管道。

## 更新与失败处理

每次建立业务连接时读取最新配置，避免进程启动后密钥永久固化。
自动发现连接发生认证失败时，最多重新读取一次配置并重新验证，不进行无界重试。
仅对连接认证进行重试，不自动重放已经提交的节点切换等写操作。
配置路径/端口变化由后续连接重新发现；正在执行的测速不热切换控制器。

保留交互 CLI 的隐藏密码输入作为最后回退；stdin 非交互或 Web 子进程时禁止调用 getpass。
错误应区分控制器不可达、需要密钥、手动密钥无效、自动配置不可读，并给出可操作说明。
前端可以看到配置来源类别和认证状态，但不能看到密钥或 Authorization header。

## 安全与兼容边界

- 不修改 Verge 配置，不硬编码截图密钥，不创建新的明文密钥配置文件。
- 密钥不进入 HTTP 响应、测速 JSONL、SQLite runs.raw、日志、异常文本或子进程命令行。
- 连接对象的 repr 不显示密钥；异常和 Web 日志针对手动及自动密钥统一脱敏。
- 手动环境变量可继承；自动密钥不注入全局 os.environ、不传播到 worker 或 IP Intelligence provider。
- 保留 localhost-only Web server、write token、Host/Origin 校验和静态文件白名单。
- 保留 Python 3.9/3.12、Windows/macOS/Linux、标准库与系统 curl 的现有依赖边界。
- 不改 Phase 1/2、节点恢复、网络评分、IP Intelligence、数据库 schema 或历史数据。

## 测试和验收

先添加能够复现当前缺少自动发现的失败测试，再实现最小修复。
所有单元测试使用临时配置和 mock API，不读真实订阅或调用真实第三方服务。

必须覆盖：

1. 无环境变量时发现当前配置并正确认证。
2. 手动参数/环境变量优先、显式空密钥语义、不自动替换错误的手动密钥。
3. 动态命名管道、TCP、自定义端口、Unix socket、IPv6 loopback 和旧默认回退。
4. 密钥含 #、冒号、空格、引号、反斜杠，以及损坏/缺失/不可读配置。
5. 远程显式地址和不匹配本机地址不会收到自动密钥；配置候选之间不交叉配对。
6. 自动密钥变化最多重读一次，写操作不被重复提交。
7. Web get_current、do_switch 和子进程路径统一认证；非交互失败不等待密码输入。
8. HTTP、日志、命令行、JSONL、SQLite 不包含 fixture 密钥；worker/provider 不继承自动密钥。
9. 全量 python -m unittest discover -s tests -v、现有 CI 相关静态检查和打包清单校验。

本机验收只执行控制器 /version、/configs、/proxies 等只读请求，不运行测速或切换节点。
Windows 实机结果与跨平台 mock 结果分别报告；没有真实 macOS/Linux 或 CI 运行时不能宣称已实机通过。

## 本地交付

先完成仓库代码、README 和测试，再备份 Downloads/Clash-SpeedBench 中将被替换的精确程序文件，
更新必要模块并校验文件 hash/打包清单；不整目录覆盖，不删除下载版额外文件。
保留 APPDATA/ClashSpeedBench 下的数据库、JSONL、令牌和用户历史。
检测下载版是否在运行；有活动测速时不终止，报告需用户中断后更新或重启。
旧后台进程不会因磁盘文件更新而自动加载新代码，需要安全退出并重新双击启动。

本次不自动 push、创建 Release、购买 API 服务或修改全局环境变量。
